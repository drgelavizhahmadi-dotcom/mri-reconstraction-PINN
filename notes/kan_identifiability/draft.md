## 3. Setup

### 3.1 Model class

We study two-layer Kolmogorov–Arnold networks of the form

```
f(x) = sum_q  g_q( T_q(x) )
```

where each **node** `T_q` aggregates univariate edge functions of the inputs, and `g_q` is a
univariate **outer** function. Two node types appear in this note:

- **additive:** `T_q(x) = sum_j psi_qj(x_j)`
- **multiplicative:** `T_q(x) = prod_j psi_qj(x_j)`

All experiments here use a single node (`q = 1`), so `f(x) = g(T(x))`. Layer 1 realizes `T`, layer 2
realizes `g`.

### 3.2 Edge parameterization as implemented

Both `psi` and `g` are `KANLinear` layers from `src/mhwf_pikan/core/fno_kan.py`. For a layer with
`in_features` inputs, `out_features` outputs, grid size `G` and spline order `k`:

| component | shape | initialization |
|---|---|---|
| `grid` (knots) | `[in_features, G + 2k + 1]` | `linspace(-1, 1, G+2k+1)`, **registered buffer — fixed, never learned or refit** |
| `base_weight` | `[out_features, in_features]` | `0.1 · N(0,1)` |
| `base_bias` | `[out_features]` | `0` |
| `spline_weight` | `[out_features, in_features, G+k]` | `0.1 · N(0,1)` |
| `spline_bias` | `[out_features]` | `0` |
| `spline_scale` | scalar | `1.0` |

The forward pass is

```
base_output   = Linear( SiLU(x); base_weight, base_bias )
x_normalized  = tanh(x)
basis         = b_spline_basis( x_normalized, grid, k )         # Cox–de Boor, [N, in, G+k]
spline_output = einsum('oib,nib->no', spline_weight, basis) + spline_bias
output        = base_output + spline_scale * spline_output
```

Three structural facts matter for what follows and are easy to miss:

1. **Every edge carries two additive paths**, a SiLU "base" path and a B-spline path, summed
   *inside* the layer. The edge function from input `i` to output `o` is
   `psi_oi(x_i) = base_weight[o,i]·SiLU(x_i) + spline_scale·sum_b spline_weight[o,i,b]·B_b(tanh(x_i))`.
2. **Biases are per-output, not per-edge.** `base_bias[o]` and `spline_bias[o]` are shared across
   all inputs `i` feeding output `o`, so they are properties of the node, not of an edge.
3. **`spline_scale` is one scalar for the whole layer**, multiplying every spline path in it. The
   product `spline_scale · spline_weight` is therefore multiplicatively redundant by construction.

Inputs are squashed by `tanh` before spline evaluation, so the spline basis always sees `[-1,1]`
regardless of the raw input range.

### 3.3 Multiplicative node

The multiplicative node reuses the same edge machinery, replacing the sum with a product
(`run_kan_multiplicative.py`). Its `base_bias` is initialized at `1.0` rather than `0` so the
product is not degenerate at initialization. Its factors `psi_j` are read out directly from the
layer rather than by marginal sweep (see §5.4).

### 4.1 Mechanical verification of exact invariance

Independent of any theorem, the following two facts about the implemented layer were verified
numerically on a trained checkpoint (`kan_gauge_check.json` @ `5845298`; `lambda = 3.0`,
tolerance `1e-5`, evaluated on a fixed batch of 500 inputs, all 4 hidden units of a `[1,4,1]` model):

| transformation | max |Δ output| over the batch | within tolerance |
|---|---|---|---|
| **whole edge** scaled by `lambda`, next layer's input divided by `lambda` | `1.19e-07` (identical on all 4 units) | yes |
| **spline path only** scaled by `lambda`, same compensation | `1.05e-02` – `4.61e-02` | **no** |

So the invariance is exact to floating-point precision when an edge is rescaled *as a whole*, and
breaks by 1–5% when only the spline coefficients are rescaled while the SiLU base path is left
untouched. The two additive paths within an edge are not independently gauge-free; only their sum
is.

## 5. Experimental setup

Everything in this section is fixed across every experiment unless explicitly noted, so that any
row of any table can be reproduced from this section alone.

### 5.1 Targets and sampling

| regime | inputs | network input | target |
|---|---|---|---|
| d=1 | `u ~ U(0.05, 4.0)` | `u / 4.0` | `exp(-u)` |
| d≥2 additive | `x1 ~ U(0.05, 4.0)`, `x2 ~ U(-1, 1)` | `[x1/4.0, x2]` | `exp(-x1) + sin(pi*x2)` |
| multiplicative | `x1 ~ U(0.05, 4.0)`, `x2 ~ U(0.05, 0.95)` | `[x1/4.0, x2]` | `exp(-x1) · sin(pi*x2)` |

`N_train = 8000`, `N_test = 2000`, drawn independently per seed. The multiplicative `x2` range is
restricted to `(0.05, 0.95)` so `sin(pi*x2) > 0` strictly and the target is positive, which makes
the power fit of §5.4 well posed.

### 5.2 Architectures

| regime | layer 1 | layer 2 |
|---|---|---|
| d=1 | `KANLinear(1, H)`, `H ∈ {1,2,4,8}` | `KANLinear(H, 1)` |
| d≥2 additive | `KANLinear(2, 1)` | `KANLinear(1, 1)` |
| multiplicative | `MultKANNode(2)` → `prod_j psi_j` | `KANLinear(1, 1)` |

`H = 1` is used for all gauge work so that d=1 and d≥2 differ only in input dimension.

### 5.3 Optimization

- Spline grid `G = 12`, order `k = 3` (cubic) throughout, except the grid sweep of §7 which uses
  `G ∈ {6, 12, 24, 48}`. **Knots are fixed at construction and are never refit per seed.**
- Adam, `lr = 3e-3`, `CosineAnnealingLR(T_max = epochs, eta_min = lr/100)`, gradient-norm clipping
  at `1.0`.
- **Full batch** — the entire 8000-sample training set is one gradient step; there is no
  minibatching and therefore no shuffle order to vary.
- Epochs: **600** for d=1, **3000** for d≥2 and multiplicative. The longer budget was adopted
  after d≥2 converged 0/10 seeds at 600 epochs; a single-seed diagnostic showed this was a
  convergence-speed issue, not a capacity one. Nothing else was changed with it.
- **Seeds `0–9`**, the same fixed list in every configuration. Each seed sets both the weight
  initialization (`torch.manual_seed(s)`) and the training/test draw (`np.random.default_rng(s)`),
  so both vary together across seeds.
- **Forced CPU** for determinism; MPS is not used anywhere in these runs. Deterministic
  re-instantiation was verified to reproduce committed results bit-for-bit (see §5.6).

### 5.4 Edge extraction

- **Additive nodes:** marginal sweep. Vary input `i` across its domain with all other inputs at
  `0`, then subtract the all-zero baseline to isolate that edge's contribution.
- **Multiplicative node:** the factors `psi_j` are read directly off the node. A marginal sweep
  with other inputs at `0` would zero the product, so direct readout is used instead — exact
  rather than inferred, and strictly more accurate than the additive convention.
- Curves are evaluated on a common grid of 300 points, identical across seeds.

### 5.5 Metrics

For a pair of independently trained seeds `(i, j)` and an edge function `phi`:

| metric | definition | free parameters |
|---|---|---|
| **RAW** | `‖phi_i − phi_j‖₂ / ‖phi_i‖₂` | 0 |
| **QUOTIENTED** | `min_{a,b} ‖phi_i − (a·phi_j + b)‖₂ / ‖phi_i‖₂`, closed-form OLS | 2 |
| **h-vs-affine** | build `h = phi1_j ∘ phi1_i⁻¹` numerically on the longest strictly monotone interval of `phi1_i`; report `QUOTIENTED`-style residual of `h` against its own best affine fit in `v` | 2 (on `h`) |
| **composition residual** | `‖phi2_i(u) − phi2_j(h(u))‖₂ / ‖phi2_i(u)‖₂`, over `u` = image of `phi1_i` | **0** |
| **propagated-(a,b)** | `‖phi2_i(u) − phi2_j(a·u+b)‖₂ / ‖phi2_i(u)‖₂` with `(a,b)` taken from layer1's fit | **0** |
| **power residual** | fit `log psi_j = log c + p · log psi_i` by least squares where both curves are `> 1e-3 · max`; residual reported in the **original** space, normalized by `‖psi_j‖` over the same sub-domain | 2 |

Inverting `phi1_i` requires monotonicity: the longest strictly monotone run is located first (a
flat step or a sign flip both count as a break, no smoothing), its extent is reported, and a pair
retaining under 10% of the grid is skipped rather than forced. For the power fit, a pair retaining
under 30% of the domain is declared inconclusive rather than counted either way.

### 5.6 Matching, filtering, and reproducibility

- **Hidden-unit permutation matching.** Hidden units are exchangeable, so same-index comparison
  across seeds assumes an alignment nothing enforces. The optimal alignment is a minimum-cost
  perfect matching, solved exactly with the Hungarian algorithm
  (`scipy.optimize.linear_sum_assignment`, O(n³)). An earlier brute-force search over all `n!`
  permutations was correct but intractable at `n = 8` (40320 permutations per pair); the
  replacement was verified to reproduce the brute-force result bit-for-bit at `n = 4`.
  Permutation matching is **not** applied across the `x1`- and `x2`-edges of a d≥2 node: those are
  semantically distinct inputs, not exchangeable units.
- **Convergence filter.** Test `R² > 0.999`, applied identically everywhere. Every table reports
  filtered and unfiltered numbers, with pair counts. §6.5 reports how much the choice of bar
  matters.
- **Reproducibility.** Models are a deterministic function of committed code plus seed. Where
  curve data was needed that result files do not store (figure F2), models were re-instantiated
  deterministically rather than retrained under new conditions; the regenerated curves reproduce
  the committed filtered QUOTIENTED to six decimals (`0.002981` vs `0.002981`).

### 6.1 Additive nodes at d≥2 are stable modulo a shared affine map

<!-- tables/T1_additive_d2_layer1.md -- source kan_multivariate.json @ 0174759 -->

**T1.** Additive d≥2 (`KAN[2→1→1]`, target `exp(-x1)+sin(pi*x2)`). Filtered = 7 well-converged
seeds / 21 pairs; unfiltered = all 10 seeds / 45 pairs. `a` is the fitted affine slope, mean ± SD
over pairs.

| edge | RAW (7-seed) | QUOTIENTED (7-seed) | a (7-seed) | RAW (10-seed) | QUOTIENTED (10-seed) | a (10-seed) |
| --- | --- | --- | --- | --- | --- | --- |
| layer1 x1-edge | 1.7311 | 0.0030 | -0.310 ± 1.197 | 2.1740 | 0.0411 | -1.368 ± 4.360 |
| layer1 x2-edge | 1.7563 | 0.0113 | -0.305 ± 1.205 | 2.4262 | 0.1996 | -0.100 ± 2.100 |
| layer2 (hidden->out) | 1.4989 | 0.5977 | -0.169 ± 0.719 | 1.3945 | 0.5651 | -0.114 ± 0.698 |

Raw disagreement between seeds is large (RAW ≈ 1.7, i.e. the difference between two seeds' curves
is comparable to the curves themselves). Quotienting by a two-parameter affine map removes
essentially all of it for layer1: 0.0030 and 0.0113. Layer2 is discussed in §6.2 — its large value
here is a transform-type artifact, not instability.

Note the fitted slope `a` is wide-spread (SD ≈ 1.2) and centered near zero. That is not an absence
of relationship: each pair has its own tight affine relation, and different pairs sit at different
points along the orbit. §6.3 separates these two readings.

**Figure F2** (`figures/F2_d2_edges_shared_affine.png`) shows this directly: raw edges scatter in
amplitude and sign; after fitting a per-seed affine map **on the x1-edge alone**, both the x1-edge
and the x2-edge collapse onto a single curve.

### 6.2 Layer2 predicted from layer1 with zero free parameters

Layer2 is the outer function `g`. Its gauge is a transformation of its **input domain**
(`g_new(u) = g_old(a·u+b)`), not a rescaling of its output values (`A·g(u)+B`). Testing it with the
latter is a category error and produces the 0.5977 in T1.

<!-- tables/T2_layer2_zero_free_parameters.md -- source kan_step10_audit.json @ 8e8ab7a -->

**T2.** Layer2 residual under four tests, ordered by how many parameters are free on the layer2
side. The first two columns **predict** layer2 with zero free parameters; only the third fits
anything to it.

| regime | derived-exact (0 free) | propagated-(a,b) (0 free) | fitted-affine (2 free) | output-affine (2 free) |
| --- | --- | --- | --- | --- |
| d=1 | 0.0070 | 0.0416 | 0.0325 | 0.4100 |
| d>=2 | 0.0251 | 0.0245 | 0.0050 | 0.5977 |

At d≥2, propagating layer1's fitted `(a,b)` into layer2 with **no free parameters at all** gives
0.0245 — indistinguishable from the exact numerical reparameterization (0.0251), and a factor of
24 below the output-affine number. The 2-parameter best case (0.0050) is the floor, not the claim.

### 6.3 The exact-vs-affine gap

Because `derived-exact` uses the true numerical `h` and `propagated-(a,b)` forces that `h` to be
affine, the ratio between them measures how far the realized reparameterization is from affine —
without depending on the absolute residual scale, and so without inheriting d=1's small pair count
in the way a single residual does.

<!-- tables/T3_exact_vs_affine_gap.md -- source kan_step10_audit.json @ 8e8ab7a -->

**T3.**

| regime | derived-exact | propagated affine | cost of forcing affine |
| --- | --- | --- | --- |
| d=1 | 0.0070 | 0.0416 | 5.91× |
| d>=2 | 0.0251 | 0.0245 | 0.98× |

Forcing `h` to be affine costs a factor of ~6 at d=1 and nothing at d≥2.

**T4.** 21 well-converged pairs.

| within-pair \|a_x1 − a_x2\|, relative | 0.0110 (1.1%) |

### 6.7 The end-to-end map

Cross-seed agreement of the full input–output map is 0.01055, and each seed's distance from the
true target is 0.01297 — a ratio of 0.813 (`kan_endtoend_stability.json` @ `0b902c6`). Seeds
therefore agree with each other no more tightly than any of them agrees with the truth, so
"the end-to-end map is identified" adds nothing beyond "training converged" and is not reported as
a finding.

## 7. Ruled out: spline-grid resolution

A natural explanation for a near-affine realized `h` at d=1 is that the finite spline grid
restricts which reparameterizations layer2 can represent, so that only near-affine `h` survives at
`G = 12`. This predicts h-vs-affine should grow with `G`. **It does not survive a confound
control and is ruled out.**

<!-- tables/T8_grid_sweep_with_matching.md -- source kan_grid_sweep.json, kan_grid_confound.json @ 0b9c1d3 -->

**T8.** Correlations over all 173 usable pairs: `corr(log₂ grid, h-vs-affine) = +0.2899`,
`corr(min pair R², h-vs-affine) = -0.4400`. Monotone within the matched band: **False**.

| grid | n well-conv. seeds | n gauge pairs | h-vs-affine (unmatched) | mean test R² | h-vs-affine (matched band) | n pairs (band) |
| --- | --- | --- | --- | --- | --- | --- |
| 6 | 2 | 1 | 0.0357 | 0.9979 | 0.0893 | 45 |
| 12 | 3 | 3 | 0.0830 | 0.9858 | 0.0738 | 28 |
| 24 | 4 | 6 | 0.1261 | 0.9478 | 0.1212 | 10 |
| 48 | 0 | 0 | n/a | 0.8625 | n/a | 0 |

The unmatched column does rise monotonically (0.0357 → 0.0830 → 0.1261). But mean test `R²` falls
monotonically along the same axis (0.9979 → 0.9858 → 0.9478 → 0.8625), and the well-converged pair
counts are 1, 3, 6, 0 — so grid and fit quality are perfectly confounded, and the trend rests on
one, three and six pairs.

Restricting to pairs of comparable fit quality (min pair `R² ∈ [0.99, 1.0]`, so that grid is the
only thing differing) removes the trend: 0.0893, 0.0738, 0.1212 — not monotone. Fit quality also
predicts h-vs-affine better (`r = -0.44`) than grid does (`r = +0.29`). At `G = 48` no pair reaches
the band at all (best seed `R² = 0.9382`).

**Conclusion: discretization does not explain the near-affine `h` at d=1.** Why it is near-affine
remains open. Untested candidates: the SiLU base path (affine in shape and not reparameterizable),
optimization inductive bias, and the fact that both models are fitting the same smooth monotone
target.

## 9. Limitations

1. **Every d=1 claim rests on at most 3 well-converged seed pairs.** The `[1,1,1]` configuration
   used for all d=1 gauge work converged on 3 of 10 seeds at 600 epochs, giving 3 pairs. The d=1
   column of T2, T3 and T5 should be read accordingly.
2. **Seeds failed to converge outright in the d≥2 and multiplicative runs, and the failures were
   not rescued by more training.** At 3000 epochs the d≥2 `KAN[2→1→1]` run left 3 of 10 seeds
   below the bar (seeds 2, 5, 8; seed 2 reached only `R² = 0.790`), and the multiplicative run left
   2 of 10 (seeds 4, 8). Extending 600 → 3000 epochs moved d≥2 from 0/10 to 7/10 — it rescued seven
   seeds and did not rescue three. **This seed-level fragility of small KANs is itself an
   observation**, not merely a nuisance: identical architectures and hyperparameters, differing
   only in seed, land in qualitatively different solutions, and no amount of additional training
   at this budget recovered them. See T7 and figure F4 for the full census.
3. **The layer2-explained-by-gauge result reverses between regimes.** d=1 (0.0070) is *better* than
   d≥2 (0.0251) on the derived-exact metric — the opposite ordering to every other comparison in
   this note. What survives the reversal is the exact-vs-affine gap (T3) and the h-vs-affine
   contrast (T5), which are about the *form* of the gauge rather than the size of the residual.
4. **Narrow experimental scope.** Targets are low-dimensional (`d ≤ 2`) and hand-chosen; a single
   architecture family (two-layer KAN with one node); a single spline basis (cubic B-splines on a
   fixed uniform knot grid); a single optimizer and schedule. Nothing here tests deeper
   compositions, multi-node layers, real data, or alternative bases.
5. **The d=1 realized gauge is near-affine for reasons unknown.** Discretization is ruled out (§7).
   Optimization inductive bias and the non-reparameterizable SiLU base path are the live
   candidates and are untested.
6. **The multiplicative prefactor/torus structure is not identified as posed.** With the outer `g`
   free, a prefactor product is absorbable downstream, and the fitted prefactor is in any case
   slaved to the exponent (`r = +0.95`). No prefactor result is reported.
